# rcpt_enum.py

Инструмент для перебора (enumeration) пользователей на SMTP-сервере через команду `RCPT TO` — пункт 5 методологии SMTP-пентеста.

> **Только для авторизованного тестирования.** Используй исключительно против хостов, явно входящих в согласованный скоуп (ROE/SOW) текущего проекта. Несанкционированный перебор учётных записей на чужой инфраструктуре может быть незаконным.

## Зачем нужен

В отличие от `VRFY`/`EXPN` (которые часто отключены администратором), команда `RCPT TO` обязана поддерживаться любым SMTP-сервером — иначе он не сможет принимать почту. Если сервер валидирует получателя до постановки письма в очередь, разница в ответе на существующий и несуществующий адрес выдаёт реальные учётные записи, даже когда VRFY/EXPN отключены или замаскированы.

Как это работает:
1. Устанавливается одно TCP-соединение.
2. Выполняется `EHLO` + `MAIL FROM` (один раз).
3. Для каждого имени из словаря отправляется `RCPT TO:<user@domain>` в рамках той же транзакции.
4. Ответ сервера классифицируется:
   - **`25x`** — адрес существует (VALID), сохраняется в outfile.
   - **`45x`** — greylisting/временный отказ (GREYLIST), результат неокончательный — тот же адрес нужно проверить повторно позже.
   - **`55x`** и другое — адрес не существует (invalid), пропускается.

## Требования

- Python 3.7+ (без сторонних зависимостей, только стандартная библиотека)

## Использование

```bash
python3 rcpt_enum.py -ip <IP> -d <DOMAIN> -w <WORDLIST> -o <OUTFILE> [опции]
```

### Обязательные параметры

| Флаг | Описание |
|---|---|
| `-ip` | IP-адрес целевого SMTP-сервера |
| `-d`, `--domain` | Домен получателя (подставляется как `user@domain`) |
| `-w`, `--wordlist` | Файл со списком имён, по одному на строку |
| `-o`, `--outfile` | Файл для сохранения подтверждённых адресов (дозапись) |

### Опциональные параметры

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-p`, `--port` | `25` | Порт SMTP |
| `--helo` | `mail.test.local` | FQDN-имя для команды EHLO (должно содержать точку — иначе сервер отклонит HELO как невалидный) |
| `--mailfrom` | `test@test.local` | Адрес отправителя для MAIL FROM |
| `--delay` | `0` | Задержка между запросами RCPT TO (сек.) — снижает риск сработать на анти-enum/rate-limit защиту |
| `--timeout` | `10` | Таймаут ожидания ответа от сокета (сек.) |

### Пример

```bash
python3 rcpt_enum.py \
  -ip 82.202.188.26 \
  -p 25 \
  -d kldp.ru \
  -w users.txt \
  -o valid_users.txt \
  --delay 0.5
```

Файл `users.txt` — простой текстовый список, например:
```
root
postmaster
admin
ivanov
petrov
```

## Особенности реализации

- **Корректный парсинг многострочного EHLO-ответа.** Postfix и другие MTA возвращают список расширений несколькими строками (`250-...` ... `250 ...`). Скрипт вычитывает их все до финальной строки без дефиса — в отличие от наивных однострочных `read`, которые десинхронизируют последующие команды (классическая ошибка в ручных bash/telnet-сессиях).
- **Автопереподключение.** Если сервер обрывает соединение посреди перебора (анти-enum защита, лимит получателей на транзакцию и т.п.), скрипт переподключается и продолжает с того же имени, не теряя прогресс.
- **Инкрементальная запись результатов.** Каждый найденный адрес сразу сбрасывается на диск (`flush()`), так что обрыв скрипта на середине словаря не теряет уже найденное.

## Ограничения и нюансы

- **Greylisting маскирует результаты.** Если сервер временно отклоняет `RCPT TO` кодом `4xx` для новых комбинаций отправитель/получатель/IP (classic greylisting), все адреса на первом проходе будут помечены как GREYLIST независимо от их реального существования. Решение — повторный прогон тем же IP/FROM через 5–15+ минут.
- **Не заменяет анализ false positive от catch-all.** Если домен настроен принимать почту на любой адрес (`catch-all`/`luser_relay`), все попытки будут давать `250 Ok` независимо от реального существования пользователя — результат в этом случае неинформативен. Проверяй контрольным запросом с заведомо случайным/абсурдным именем: если оно тоже даёт `250`, домен catch-all и перебор бессмыслен.
- **Не маскирует источник.** Запросы идут напрямую с твоего IP без прокси/Tor — учитывай это при планировании теста и согласовании с заказчиком (IP может быть залогирован и заблокирован целевой стороной).
